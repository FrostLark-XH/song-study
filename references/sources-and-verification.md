# 来源与核验

## 识别与获取

利用歌手、原名、专辑、语言等识别作品。信息不足先搜索；同名不同作品或录音差异会影响请求内容时才集中确认。默认录音室完整版，保存具体版本；翻唱证据不能自动证明原录音读法。

按 A 用户提供文本/链接 → B 官方 → C 歌词平台/数据库 → D 其他页面/字幕尝试；仍未取得时 E 换原名、假名、罗马字等针对性重搜。可访问性与证据质量分别判断，不笼统把 Genius、uta-net、Musixmatch 全标为“授权”。用户给链接也须实际打开读到内容；已提供文本可直接处理，来源身份另记。

使用当前可用搜索/页面工具，合并独立查询、去重结果。默认最多尝试约四个不同渠道，别名搜索不是新渠道；拿到版本匹配、结构完整的可靠来源即可停止，冲突/缺段才追加核对。预算或渠道耗尽就说明未获取到/不完整，交付现有可用材料；不得用同类镜像反复凑检索次数。403、空结果只说明访问或检索失败，不说明歌曲没有歌词。不要绕过登录、付费或访问控制。

逐行比较原文，检查首末句、段落顺序、每次重复和变体，区别演唱行数与唯一文本数。网页行数可能包含假名/换行，不直接当歌词行数。不完整的 Genius 页面等不能仅因平台知名就采用。OCR/ASR 仅作候选，模型记忆不作主源或补全。格式差异与文字错漏分别记录，不为匹配来源而删掉重复副歌。

同版本、原文未变且已有实际比对记录可沿用，不为每次视觉修改重新联网。背景、文化及作者意图的关键断言须有可定位证据；仅有历史 URL 和旧总结不足以沿用为确定事实，按 learning-content.md 的关联规则补查。历史来源没有 URL 如实标缺失，不能把过去的来源名当本次已打开。获取全文与允许再分发分开判断；按当前环境版权规则提供允许的内容，用户提供的文本可继续处理。

## 记录形态

- `verification.lyrics.sources`：对象列表，`id/url/title/fetched_at/version`；历史 URL 可为 null，日期只写真实获取日期。coverage 等补充信息可在描述/核验 note 中记录。
- `verification.lines`：ID→状态的逐行登记。现有校验器称其数量为 cited_lines，实际上只数 ID 是否有条目，并不验证条目含 URL 或真的完成比对；不要把它报告为真实来源覆盖。
- `verification.lyrics.text_compared`：可读说明，记录本次/沿用哪份来源、实际比对范围、分母（演唱行数）和结果；未比对就写未比对。`diff_summary` 列具体行 ID、两侧差异及处理理由。原文一致不等于注音翻译也检查过。
- `verification.license`：使用范围单独记录。不把已核验解释为可商用。

状态词表：`已核验` / `局部待核验` / `待核验` / `文本不完整` / `未获取到` / `使用范围受限`。每项写 `status + note`，note 给证据、范围与缺口；行状态标已核验须有实际核对，不能因为填了登记就升级。

| checks 键 | 本项证明什么 |
| --- | --- |
| song_version | 歌曲、歌手及采用录音版本识别；证据定位清楚 |
| lyric_text | 实际与来源原文比对；覆盖、差异与冲突写清 |
| reading_translation | 注音、翻译核对的行范围；标准读法与录音证据另分清 |
| structure | 数据、ID、段落/页面顺序、覆盖和产物结构的实际检查 |
| render | 当前成品实际渲染的后端、页数、成功/失败，不替代看图 |
| visual | 检查者、实际查看的页、排版/美术问题与未完成范围；AI 检查与用户审美反馈分开 |

不合并六项为“全部通过”。新改动只使受影响证据失效：歌词原文改动重查原文及相关读音翻译；单改译文重查翻译；单改颜色重查视觉；换版本重查版本相关内容。指纹告警提示可能过期，需要按差异定位，不要求无条件重查全曲。修改后只刷新指纹不构成核验。

## 生成后检查

交付前做一次针对性的找错检查，优先检查数字典故、作者意图、绝对措辞、多义词及跨章节矛盾；回到原始证据核对，不以同一模型自我确认或另一模型赞同作为通过依据。

校验器 PASS 表示它覆盖的程序检查通过；不能证明网站来源可靠、语言正确或视觉好看。error 在任务范围内修复；warning 阅读、修复或说明。全文检查、局部检查与模拟测试分别记录；没有真实联网或没有看图不要冒充。

首次完整制作：渲染完整 PPT/DOCX，核对页数与当前文件回执；查看整曲缩略图及长句、深色、异常注音等页大图。局部改版：重渲染实际新成品，复查改动与相邻页、整曲缩略图，未改部分仅沿用有文件/范围记录的旧检查。没有旧视觉证据时仍按首次检查处理。无法回显图片只记录管线与文本检查，visual 保留待核验。AI 能记录具体美术问题与已看范围，不能冒充用户确认。

回执中的 PPT 文件哈希用于绑定本次渲染；回归比较解包后的内容，不用会受 ZIP 时间戳影响的整包哈希判断行为变化。一份简短记录足够，注明真实完成和缺口，不重复生成多套报告。
